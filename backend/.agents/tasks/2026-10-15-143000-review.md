# MCQ distractor-quality fix — pass 2 (all prior findings addressed)

The previous pass issued `CHANGES_REQUESTED` on two blocking findings: a `[:60]` truncation in `seen_lower` that allowed near-identical long candidates past the dedup gate, and the supplement loop silently dropping difficulty-overlap semantics for thin pools. Both are fixed in this revision. Two non-blocking findings — an untested inner similarity gate in `_build_mcq` and no hard-difficulty coverage — are addressed with new test methods in `DistractorQualityDBMSTest`.

Watch for: (1) **possible** — `test_build_mcq_inner_similarity_gate_rejects_near_duplicate` calls `_assemble_quiz`, not `_build_mcq` directly; if the pool-level gate eliminates every near-duplicate first, the inner gate in `_build_mcq` remains unexercised. (2) **possible** — the hard-difficulty test allows zero questions from the DBMS source, making the structural assertions vacuously satisfied if the `overlap < 0.05` filter is too strict for that corpus.

**Verdict**: APPROVED

## High-level view

Both blocking findings are confirmed fixed. Finding 1: `cand_lower = candidate.lower()` (no slice) in both the main and supplement loops; the membership check and the similarity gate now operate on the same representation. Finding 2: the overlap logic is extracted into a shared `_fails_difficulty_overlap` closure called from both loops.

The Finding 3 test goes through `_assemble_quiz` rather than `_build_mcq` directly. The combined end-to-end assertion still catches a regression if the inner gate is removed — but only because the pool-level gate would also need to have been removed; the two gates are not independently tested. The hard-difficulty test documents that zero questions is acceptable from the DBMS source, which means the test body may never execute.

### Finding 3 test scope (possible)

`test_build_mcq_inner_similarity_gate_rejects_near_duplicate` constructs a 7-sentence source where two sentences produce near-identical predicates and asserts that no distractor in any generated MCQ exceeds 0.85 similarity to its question's correct answer. This catches a regression in either the pool-level gate or the inner gate — but cannot distinguish which one is doing the work. If the pool gate is the sole operative filter, the inner gate in `_build_mcq` could be deleted without this test failing. The prior review explicitly requested a direct `_build_mcq` call; the test uses `_assemble_quiz` instead.

### Hard-difficulty structural assertions (possible)

The test documents "It is acceptable if hard difficulty produces 0 questions from DBMS source" and skips all structural assertions in that case. The DBMS 13-sentence source may consistently produce zero hard-difficulty questions because the `overlap < 0.05` filter is strict. If it always returns empty, `test_hard_difficulty_produces_valid_questions` is a no-op for every run against this corpus. The `overlap < 0.05` path would only be exercised by a richer source (e.g., the 15-sentence OS source used in `QuizAnswerEvalTest`).
